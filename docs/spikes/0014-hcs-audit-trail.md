## Reproduction inputs

This experiment pins `@hiero-ledger/sdk` separately and changes no workspace dependency or lockfile. Its client targets loopback with synthetic account/topic IDs and no operator. The script freezes and serializes only; `submitCommitment` is an unexecuted usage sketch accepting a caller-supplied client and fee cap. Its single-chunk example does not implement production validation, custom-fee policy, retry or signer setup.

Commands and pinned runtime inputs are in the [offline reproduction how-to](../../scripts/spikes/hcs-audit-reproduction.md).

Both runtime commands exit 0 and print `Verified offline: SDK freeze/round-trip; 87-byte envelope; mirror match, lag and rejection fixtures. No execute/getReceipt/network calls.`

The fixtures do not prove consensus or a real mirror response. A future console must recompute the expected message from an authenticated private opening before comparing bytes. Matching a mirror response trusts that mirror; it does not prove completeness or truth of the source event. Salt leakage enables candidate checking only if the attacker also knows or guesses every event field, including its random event identifier; public payer metadata and timing still permit correlation. See ADR 0014 for the proposed privacy boundary.

## Limits of the fixtures

**Read from source:** byte equality is the only message-shape check. There is no independent parser or explicit extra-field, missing-field or valid-Base64 wrong-commitment fixture. The `chunk_info.total === 1` branch is not exercised. The locator is a decimal string, but the response sequence is parsed as a JSON number; unsafe integers reject. Lossless int64 handling remains Open.

**Open:** distinct console outcomes for transport errors, missing openings and mismatches; production retry and transaction-identifier lookup; compatibility with the merged record format. `submitCommitment` is an exported, uninvoked usage sketch. Importing this script runs the offline experiment; it is not a library entry point.
